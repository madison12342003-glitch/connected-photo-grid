# Illustration and Element Layer

## Source priority
Use the following order:
1. Elements already present in the user's photographs, including carefully cropped details.
2. Elements grounded in the actual scene and explicitly approved by the user.
3. Licensed or otherwise permitted asset-library elements.
4. Newly generated assets, only when they fill a real design need.

Do not assume every regional project needs the same symbols. Never add a yak, flower, religious icon, flag, or architectural motif solely because it is stereotypically associated with a region.

## Asset styles
Prefer a limited visual language that complements real photography:
- fine black line art
- restrained red woodcut or screen-print shapes
- simple monochrome silhouettes
- lightly textured editorial illustrations

Avoid glossy 3D, random sticker packs, mixed illustration styles, and photorealistic generated objects pasted into documentary photos.

## Asset metadata
Maintain a small manifest for reusable assets with:
- asset_id
- descriptive name
- source: user-photo, scene-derived, licensed, or generated
- source/permission notes
- visual style
- palette
- transparent-background status
- preferred scale and placement
- can_cross_grid
- cultural or contextual constraints

## Regional accuracy
Use scene evidence first. A flower photographed in the trip can be extracted or redrawn as a motif. If an animal or cultural object was not present in the photographs, treat it as optional illustration rather than documentary evidence. For sacred or religious imagery, favor respectful, context-aware treatment and do not use it as meaningless decoration.

## Generation workflow
Generate individual assets, not the entire collage, when consistency and editability matter. Request a clean silhouette or transparent background where appropriate. Inspect anatomy, cultural details, and edges manually before use. Keep a record that the asset is generated.
